## Exact confirmed defects and repairs

1. **Walk-in retry after undo claimed confirmed:** old actual function replay returned `result=confirmed` even after check-in was undone. Local pre-fix assertion failed with `undo_replay_claimed_confirmed`, exit 3. Replay now returns the explicit existing-registration path when no longer admitted, and rechecks current payment/consent blockers for still-checked-in replays. It never silently re-admits cancelled/undone attendees.
2. **Existing-registration success lacked a receipt:** the sheet treated any error-free `check_in_rsvp` void response as new success, including already-checked-in races. Pre-fix component assertion failed because close/success were called on an empty response. `check_in_admission` locks and delegates to the unchanged guarded function, returns `ok/already/undone`, and the UI requires that receipt. Manual roster/retry calls use it too; duplicate analytics are not counted as new admissions, undo is no longer described as already checked in.
3. **Editable in-flight identity and stale resolution:** pre-fix component assertion failed because email stayed editable during a pending admission. Fields now lock during requests, and editing identity clears the previous existing-registration target. Failed requests retain values and reuse the exact request key. Successful resolution clears fields/request identity.
4. **Counts drift and merged roster duplication:** old attendance_totals counted a cancelled party of three as three checked in; isolated before output `3`, corrected output `0`. It now counts only going checked-ins, excludes merged rows, and returns active walk-in person totals. Check-in counters use staff-authorized attendance_totals rather than the differently-scoped public/live counter source. The roster excludes merged rows and cancelled check-ins; mutation/realtime refreshes invalidate both roster and totals, with 15-second/focus refresh fallback. Registered includes going/maybe persons; checked-in includes going persons; walk-ins includes active going/maybe walk-in persons; cancelled remains registration-row count for compatibility. Row-list headings remain registration rows, not party-person totals.
5. **Upcoming date/time used viewer timezone:** card previously used browser date/getDate and locale time without event timezone. It now formats month/day/time in the event timezone. Concrete test: Nov 1 00:30 UTC must show Oct 31, 5:30 PM in Los Angeles.

There is no attendee acceptance step in the current staff form. Local actual blocker returned **platform_agreement_required** and rolled the candidate back (zero row).
